D. O QUE DEPENDE DO USUARIO
------------------------------------------------------------------------------------------------------
D1. Instalar Docker Desktop (com WSL2)
  Acao necessaria: instalar o ambiente de containers para subir o Airflow.
  Programa ou site: Docker Desktop para Windows (https://www.docker.com/products/docker-desktop/) e WSL2.
  Arquivo envolvido: nenhum.
  Caminho do menu ou procedimento: PowerShell como Administrador -> "wsl --install" -> reiniciar -> instalar Docker
    Desktop -> Settings > General > "Use the WSL 2 based engine" marcado.
  Passo a passo:
    1. Abrir PowerShell como Administrador e executar: wsl --install
    2. Reiniciar o computador quando solicitado.
    3. Baixar e instalar o Docker Desktop; abrir e aguardar "Engine running".
    4. Em Settings > Resources, reservar pelo menos 4 GB de memoria (o Airflow standalone usa ~2 GB).
    5. No PowerShell comum: docker version
  Resultado esperado: "docker version" mostra Client e Server.
  Como saber se deu certo: "docker run --rm hello-world" imprime "Hello from Docker!".

D2. Subir o Airflow e executar a DAG
  Acao necessaria: subir o Airflow 2.10.5 e disparar acessacidade_elt_pipeline.
  Programa ou site: Docker Desktop + navegador (http://127.0.0.1:8080).
  Arquivo envolvido: 02-Big-Data-Architecture/airflow/docker-compose.airflow.yml; .env da raiz (opcional).
  Caminho do menu ou procedimento: UI do Airflow > DAGs > acessacidade_elt_pipeline > botao de ativar > Trigger DAG.
  Passo a passo:
    1. Feche o notebook/qualquer processo usando data/processed/warehouse/acessacidade.duckdb.
    2. cd C:\Users\masak\Desktop\GS7-4ESPR\02-Big-Data-Architecture\airflow
    3. Sem API: docker compose -f docker-compose.airflow.yml up -d
       Com API: docker compose --env-file ..\..\.env -f docker-compose.airflow.yml up -d
    4. docker compose -f docker-compose.airflow.yml logs -f airflow  (aguardar "Airflow is ready"; Ctrl+C sai do log)
    5. Senha: docker compose -f docker-compose.airflow.yml exec airflow cat /opt/airflow/standalone_admin_password.txt
    6. Abrir http://127.0.0.1:8080, entrar com usuario admin e a senha do passo 5.
    7. Ativar (unpause) a DAG acessacidade_elt_pipeline; clicar em Trigger DAG (ou "Trigger DAG w/ config" com
       {"usar_api": false} para rodar sem API).
    8. Abrir a visao Graph e aguardar as 6 tarefas ficarem verdes; abrir Logs de cada tarefa.
  Resultado esperado: 6 tarefas "success"; log de quality_report com "situacao: APROVADO"; arquivos em
    data/processed/gold/ com data/hora atualizadas.
  Como saber se deu certo: Graph todo verde; data/processed/gold/gold_snapshot.json com "execucao_id" igual ao run_id
    do Airflow (ex.: "manual__2026-11-...").
  Observacao: se a instalacao do duckdb pelo _PIP_ADDITIONAL_REQUIREMENTS falhar (sem internet), a DAG aparece com
    erro de importacao "No module named duckdb" no topo da UI.
